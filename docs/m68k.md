# Motorola 68000 core (`ens_m68k`)

Instantiable 68000 core for the KS-32 emulator: one instruction or exception per `Cpu::step()`,
with the cycle count of its bus cycles plus internal clocks. Source: `src/m68k/`. Decisions:
`docs/decisions.md`, section "68000 core" (M1, M3, M5, M6, M9, M11-M13, ...).

## API (`src/m68k/m68k.h`)

- `Bus`: `read8/read16/write8/write16` at 24-bit addresses (word accesses at even addresses),
  `interruptAcknowledge(level)`, `resetPeripherals()`. No bus-error return, no function codes (M5).
  Long accesses are two word accesses in the suite's order (M13).
- `Cpu(Bus&)`: `reset()`, `step()`, `run(cycles)` (M6), `setIpl()`, `regs()`/`setRegs()`,
  `instructionAddress()`, `exceptionCount(vector)`, `halted()`/`stopped()`, `totalCycles()`.
- `Registers`: `d[8]`, `a[7]` (A0..A6), `usp`, `ssp`, `pc`, `sr`, `prefetch[2]`.

## Conventions

- M3: `Registers::pc` is the formal program counter, the address of the next instruction, and
  `prefetch` is the two-word queue (the words at `pc` and `pc + 2` at an instruction boundary).
  This is exactly the suite's convention, so `setRegs` takes a suite initial state 1:1 and
  `regs()` is compared 1:1 with a suite final state.
- Cycle counts are total clocks, 4 per bus cycle, as in the suite's `length`.
- A word or long access at an odd address never reaches the `Bus`: it takes the address-error
  exception (vector 3, 14-byte frame, the clocks run before the fault plus 50; M11, M12). An
  address error during reset or during address-error processing halts the CPU (M9).
- Privileged instructions in user mode take the privilege-violation exception (vector 8, 34
  cycles, the instruction's address stacked).

## Tom Harte's per-instruction suite

The suite is not in the repository (`.gitignore` has `testdata/`). Download it into
`testdata/680x0/68000/v1/` (124 files `NAME.json.gz`, about 8 065 tests each, 1 000 060 in
total, plus its README.md), then convert it:

    python -I tools/m68k_harte/convert_harte.py testdata/680x0/68000/v1 testdata/680x0/68000/m68t
    python -I tools/m68k_harte/convert_harte.py --json one.json out.m68t     # one plain JSON file

The converter uses only the standard library and writes one `.m68t` per input (about 257 MB
in all). Format (little-endian): `"M68T"`, `u32 version = 1`, `u32 count`; each test
`u16 nameLen`, the name, `State initial`, `State final`, `u32 cycles`; `State` is
`u32 d[8], a[7], usp, ssp, pc`, `u16 sr`, `u16 prefetch[2]`, `u32 ramCount`, then
`ramCount x (u32 addr, u8 value)`. `transactions` are not kept.

Run it (CMake option `ENS_M68K_TESTS_DIR`, default `<source>/testdata/680x0/68000/m68t`):

    build/m68k_harte <dir> [--only NAME[,NAME]] [--max-fail N]

It prints `NAME: pass/total (smp a, aef b)` per file and a `total:` line; for the first
`--max-fail` (default 3) failing tests of each file it prints the name and the first 3
differences (`field: expected X, got Y`). Exit code 0: all pass, or `skip: test data not found`
when the directory has no `.m68t`; 1: any failure; 2: usage error or corrupt data. The whole
suite runs in a few seconds. `ctest` runs it as `m68k_suite`.

Pass criterion (M1): registers, prefetch queue, cycles and RAM must all match; the two classes
`smp` (self-modifying prefetch) and `aef` (address-error frame) are counted as passes and shown
separately.

Test names inside the files are "OPCODE [MNEMONIC operands] n". Several instructions share the
file of the base operation: the immediate forms appear as `ADD.b #, ...` (ADDI, opcode 06xx) and
`ADD.b Q, ...` (ADDQ) inside `ADD.*`; likewise `SUB.*`, `CMP.*` (CMPI), `AND.*` (ANDI),
`OR.*` (ORI) and `EOR.*` (EORI); `MOVE.q` is MOVEQ; the shift and rotate count forms (`Q` or `Dn`)
share the file of the operation.

### Suite file to task

| Task | Suite files (`.json.gz`) |
|------|--------------------------|
| 2 (runner) | NOP |
| 3: data movement, effective addresses, address errors | MOVE.b, MOVE.w, MOVE.l, MOVE.q, MOVEA.w, MOVEA.l, MOVEM.w, MOVEM.l, MOVEP.w, MOVEP.l, LEA, PEA, EXG, EXT.w, EXT.l, SWAP, LINK, UNLINK, CLR.b/w/l, MOVEfromUSP, MOVEtoUSP |
| 4: arithmetic, BCD, multiply/divide, CHK, TST, CMP | ADD.b/w/l, ADDA.w/l, ADDX.b/w/l, SUB.b/w/l, SUBA.w/l, SUBX.b/w/l, NEG.b/w/l, NEGX.b/w/l, ABCD, SBCD, NBCD, MULS, MULU, DIVS, DIVU, CHK, TST.b/w/l, CMP.b/w/l, CMPA.w/l |
| 5: logic, shifts, bits, Scc, TAS | AND.b/w/l, OR.b/w/l, EOR.b/w/l, NOT.b/w/l, ASL.b/w/l, ASR.b/w/l, LSL.b/w/l, LSR.b/w/l, ROL.b/w/l, ROR.b/w/l, ROXL.b/w/l, ROXR.b/w/l, BTST, BCHG, BCLR, BSET, Scc, TAS |
| 6: program control, system, SR/CCR, traps, RESET | Bcc, BSR, DBcc, JMP, JSR, RTS, RTR, RTE, TRAP, TRAPV, RESET, MOVEfromSR, MOVEtoSR, MOVEtoCCR, ANDItoCCR, ANDItoSR, ORItoCCR, ORItoSR, EORItoCCR, EORItoSR |

The table covers all 124 files (1 + 23 + 38 + 42 + 20).
Immediate forms (ADDI/ADDQ, SUBI/SUBQ, CMPI, ANDI, ORI, EORI) are tested in the base-operation
file, so they belong to the task that owns that file.
