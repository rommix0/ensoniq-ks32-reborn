# Motorola 68000 core (`ens_m68k`)

Instantiable 68000 core for the KS-32 emulator: one instruction or exception per `Cpu::step()`,
with the cycle count of its bus cycles plus internal clocks. Source: `src/m68k/`. Decisions:
`docs/decisions.md`, section "68000 core" (M1-M24).

## API (`src/m68k/m68k.h`)

- `Bus`: `read8/read16/write8/write16` at 24-bit addresses (word accesses at even addresses),
  `interruptAcknowledge(level)`, `resetPeripherals()`. No bus-error return, no function codes (M5).
  Long accesses are two word accesses in the suite's order (M13).
- `Cpu(Bus&)`: `reset()`, `step()`, `run(cycles)` (M6), `setIpl(level)` (M7), `regs()`/`setRegs()`,
  `instructionAddress()`, `exceptionCount(vector)`, `halted()`/`stopped()`, `totalCycles()`.
- `Cpu::onInstruction`: an optional `std::function<void(uint32_t pc)>`, called with the address
  of each instruction just before it executes (the debug trace hook; not called for
  exceptions, interrupts or idle steps).
- `disassemble(read16, addr)` (`src/m68k/m68k_dis.h`, `src/m68k/m68k_dis.cpp`): the debug-trace
  disassembler. It reads the instruction's words through a `read16` callback and returns a
  `DisLine` (`length` in bytes, 2..10, and the Motorola-syntax lower-case `text`); words that
  are illegal or line A/F print as `dc.w`.
- `Registers`: `d[8]`, `a[7]` (A0..A6), `usp`, `ssp`, `pc`, `sr`, `prefetch[2]`. `regs()` and
  `setRegs()` read and set the architectural state at an instruction boundary, for tests and
  debugging. They are not a save state: stopped, halted, a pending trace, the level 7 latch and
  the IPL are not in `Registers` (and `setRegs` clears only the pending trace), and `setRegs`
  masks SR with 0xA71F.
- Interrupts (M4, M7, M24): `setIpl(level)` latches the request level; at each instruction
  boundary a level above the SR mask is taken (level 7 also once per rise), with a 44-cycle
  entry. `Bus::interruptAcknowledge(level)` supplies the vector (`kAutovector`, `kSpurious` or
  0..255).

## Conventions

- M3: `Registers::pc` is the formal program counter, the address of the next instruction, and
  `prefetch` is the two-word queue (the words at `pc` and `pc + 2` at an instruction boundary).
  This is exactly the suite's convention, so `setRegs` takes a suite initial state 1:1 and
  `regs()` is compared 1:1 with a suite final state.
- Cycle counts are total clocks, 4 per bus cycle, as in the suite's `length`.
- A word or long access at an odd address never reaches the `Bus`: it takes the address-error
  exception (vector 3, 14-byte frame, the clocks run before the fault plus 50; M11, M12). An
  address error during reset or during address-error processing halts the CPU (M9).
- Privileged instructions in user mode take the privilege-violation exception (vector 8, 34
  cycles, the instruction's address stacked): ANDI/ORI/EORI to SR, MOVE to SR, MOVE USP, RTE,
  RESET and STOP. MOVE from SR is not privileged on the 68000.
- Trace (T = 1 at the start of an instruction that is executed, UM 6.3.8) is vector 9 and a
  `step()` of its own, after the instruction (also after TRAP, TRAPV, CHK and divide by zero,
  not after an illegal or privileged instruction or an address error). It also ends a STOP.
- STOP loads SR and sets `stopped()`; a stopped CPU idles (M6) until an exception ends it
  (a trace exception, or an interrupt above the SR mask, M7). RESET calls `Bus::resetPeripherals()` and takes 132 cycles (M8).

## Tom Harte's per-instruction suite

The suite is not in the repository (`.gitignore` has `testdata/`). Download it into
`testdata/680x0/68000/v1/` (124 files `NAME.json.gz`, about 8 065 tests each, 1 000 060 in
total, plus its README.md), then convert it:

    python -I tools/m68k_harte/convert_harte.py testdata/680x0/68000/v1 testdata/680x0/68000/m68t
    python -I tools/m68k_harte/convert_harte.py --json one.json out.m68t     # one plain JSON file

The converter uses only the standard library and writes one `.m68t` per input (about 257 MB
in all). Format (little-endian): `"M68T"`, `u32 version = 1`, `u32 count`; each test
`u16 nameLen`, the name, `State initial`, `State final`, `u32 cycles`; `State` is
`u32 d[8], a[7], usp, ssp, pc`, `u16 sr`, `u16 prefetch[2]`, `u32 ramCount`, then
`ramCount x (u32 addr, u8 value)`. `transactions` are not kept.

Run it (CMake option `ENS_M68K_TESTS_DIR`, default `<source>/testdata/680x0/68000/m68t`):

    build/m68k_harte <dir> [--only NAME[,NAME]] [--max-fail N]

It prints `NAME: pass/total (smp a, aef b, dev c)` per file and a `total:` line; for the first
`--max-fail` (default 3) failing tests of each file it prints the name and the first 3
differences (`field: expected X, got Y`). Exit code 0: all pass, or `skip: test data not found`
when the directory has no `.m68t`; 1: any failure; 2: usage error or corrupt data. The whole
suite runs in a few seconds. `ctest` runs it as `m68k_suite`.

`build/m68k_harte --bench` runs a fixed synthetic instruction mix (MOVE.l/MOVE.w across modes,
ADD, CMP, Bcc, DBF, JSR/RTS, LSL, MULU) from RAM for 300 M cycles and prints the speed in M
cycles/s; it exits 1 if the mix took an exception. The target is at least 61 M cycles/s (4 x the
KS-32's 15.238 MHz) on MSVC x64 Release; Task 9 measured about 665 there and 630 on MinGW i686
(`docs/verification-plan5.md`).

Pass criterion (M1): registers, prefetch queue, cycles and RAM must all match; the two classes
`smp` (self-modifying prefetch; the suite has no such case, the class is kept as a guard) and
`aef` (address-error frame: vector 3 taken, everything exact except bits 3..0 of the status
word's low byte, M12) are counted as passes and shown separately, and so is `dev`: a failing
test listed by exact name in the manual-deviation table of `src/m68k/harte_format.cpp`, where a
decision follows the PRM/UM against the suite and where only the fields the entry names may
differ (at present DIVU "80ef [DIVU (d16, A7), D0] 5745", M15, RAM 0x7FF only, and two ASL.b
cases with inconsistent recorded states, M19, D2 and for one the condition codes). A listed
test that passes prints a `WARNING stale manual deviation` line.

Test names inside the files are "OPCODE [MNEMONIC operands] n". Several instructions share the
file of the base operation: the immediate forms appear as `ADD.b #, ...` (ADDI, opcode 06xx) and
`ADD.b Q, ...` (ADDQ) inside `ADD.*`; likewise `SUB.*`, `CMP.*` (CMPI), `AND.*` (ANDI),
`OR.*` (ORI) and `EOR.*` (EORI); `MOVE.q` is MOVEQ; the shift and rotate count forms (`Q` or `Dn`)
share the file of the operation.
