# 68000 CPU Core Implementation Plan (Plan 5)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build an `m68k` library: a Motorola 68000 core that runs every instruction and addressing mode, with exceptions and interrupts and cycle-exact instruction timing. It must pass the per-instruction 68000 test suite on both toolchains and run at least 4× real time, ready for the KS-32 machine (Plan 6).

**Architecture:** The core is an instantiable C++17 class, `ens::m68k::Cpu`, written from Motorola's manuals the way the chip cores were written from their datasheets.

- **Bus.** It talks to the machine through a `Bus` interface: byte and word reads and writes, interrupt acknowledge and the RESET line. This is the same pattern as `WaveMemory` and `EspBus`.
- **Decode.** One pure decoder (`decodeOp`) classifies every 16-bit opcode word. Each `Cpu` fills its own 64K-entry dispatch table from it, and the debug-trace disassembler uses the same decoder, so the core and the disassembler always agree on what is valid.
- **Instruction families.** These live in separate source files.
- **Test suite.** A converter turns the downloaded per-instruction suite into a compact binary form. A runner tool executes it and becomes each task's test.

**Tech Stack:**
- C++17 and CMake 3.20+, with `tests/check.h`.
- No third-party libraries.
- One Python 3 standard-library script (`python -I`) to convert the test data.
- Reference documents, downloaded with permission in Task 1:
  - Motorola *M68000 Family Programmer's Reference Manual* ("PRM");
  - Motorola *M68000 8-/16-/32-Bit Microprocessors User's Manual* ("UM"), whose §8 has the instruction execution times;
  - Tom Harte's 680x0 ProcessorTests, 68000 set ("the suite"), MIT licence, used as test vectors, not code.

**Spec:** `docs/design/2026-10-21-ks32-machine-and-juce-app-design.md` ("design"), revised 2026-10-23 and approved. Plan 5 builds the §7 layer 1 and goal 1 (§2). Its row in §9 reads: "The `m68k` library and its debug-trace disassembler, passing the per-instruction test suite with cycle counts". The firmware is **not decompiled** (§5). The disassembler serves only the emulator's debug trace. This plan produces no firmware listing and commits nothing taken from the ROM. Judgment calls go in `docs/decisions.md`.

## Global Constraints

- **Language and dependencies.** C++17. No third-party libraries in the repository. The suite data is downloaded into `testdata/` (git-ignored, added in Task 2) and never committed.
- **Pure core.** `src/m68k` has no OS calls, no threads, no file I/O and no mutable globals or statics. Every `Cpu` can be instantiated many times (design §5, §7).
- **Integer only.** `src/m68k` uses no `float` or `double`. State and cycle counts must be bit-identical across the MSVC x64 and MinGW i686 builds (design §6).
  - No undefined behaviour on either build: no signed overflow, no shift by ≥ the type width, no `INT_MIN / -1`.
- **Builds.** Everything builds with VS 2022 x64 (`-G "Visual Studio 17 2022" -A x64`, `build-msvc/`) and with MinGW g++ 14 plus Ninja (`build/`), without warnings at `/W4` and `-Wall -Wextra`.
  - Git Bash cannot launch the MinGW executables, so run them from PowerShell.
- **References.** The references are the PRM and the UM. Where they say "undefined", or are silent, the suite's vectors are the evidence. MAME is a comparison point only (design §5).
- **Decisions.** Every choice the manuals do not settle is marked `// DECISION <id>: <one line>` at the point of use. It gets a `docs/decisions.md` entry under a new `## 68000 core` heading (options, choice, evidence, confidence, status). The ids are **M1–M10** (table below), then M11 onward in order of discovery.
- **Downloads.** Each needs the user's explicit permission. The controller asks in Task 1, Step 0.
- **ROM tests.** Tests that need the KS-32 ROM use `ENS_ROM_DIR`. Without it they print `  skip: ROMs not found` and pass.
  - The suite runner prints `skip: test data not found` and exits 0 when `ENS_M68K_TESTS_DIR` is missing.
- **Branch.** Work on branch `plan5-m68k-core` and commit after each task.

## Decision Defaults (M-ids)

| Id | Topic | Default (my call unless noted) | Task |
|---|---|---|---|
| M1 | Suite pass criterion | The runner compares the final D0–D7, A0–A6, USP, SSP, PC, SR, the two prefetch words, every RAM byte the test lists, and the total cycle count. It does not compare the order of bus transactions. Two failure classes are counted separately and allowed, but only these two: (a) **self-modifying prefetch**, where the instruction writes into its own prefetch window [instruction address, +6) (the firmware runs from ROM); (b) **address-error frame detail**, where vector 3 is taken, the stacked SR and PC match, and only the first 8 bytes of the 14-byte frame differ (status word, access address, IR). All other failures are bugs. | 2, 9 |
| M2 | Undefined flags and results | Where the PRM says "undefined" (for example N/Z/V of DIVU/DIVS on overflow, N/V of ABCD/SBCD/NBCD, the CHK flags), follow the suite. | 4, 5 |
| M3 | PC and prefetch convention | The core models the 68000's two-word prefetch (IR and IRC) as the UM describes. The meaning of the suite's `pc` and `prefetch` fields is taken from its README. `Registers::pc` uses the same convention, so `setRegs` and `regs` map onto the suite 1:1. | 1, 2 |
| M4 | Interrupt exception timing | 44 cycles (UM exception table) for both vectored and autovectored interrupts. There is no E-clock synchronisation jitter, so the core stays deterministic. | 7 |
| M5 | Bus errors and function codes | The `Bus` interface has no bus-error return and no function-code lines. No KS-32 source for either is known (Plan 6 may add them). Vector 2 is never taken. | 1 |
| M6 | Run slices | `run(n)` executes whole instructions and exceptions until at least n cycles have passed, then returns the cycles used (the overshoot is at most one instruction). A stopped or halted CPU consumes exactly n. Results do not depend on how the caller slices time. | 1, 7 |
| M7 | Interrupt sampling | IPL is sampled at instruction boundaries. Levels 1–6 are level-sensitive against the SR mask. Level 7 is edge-triggered: one interrupt per rise to 7, whatever the mask. | 7 |
| M8 | RESET instruction | 132 cycles (UM). It calls `Bus::resetPeripherals()` and leaves the CPU state unchanged. | 6 |
| M9 | Double fault | An address error during group-0 exception processing, or during reset, halts the CPU. `halted()` becomes true and only a new `reset()` clears it. | 3 |
| M10 | DIVU/DIVS cycles | The data-dependent counts the suite expects. The UM gives only upper bounds (140 and 158). The algorithm is written down with its evidence in the entry. | 4 |

## Review Focus

1. **Too slow for real time.** The machine runs the CPU at 15.238 MHz alongside OTIS and the ESP inside an audio callback, so the core needs headroom. Test: `m68k_harte --bench` reports at least 61 M cycles/s (4 × 15.238 MHz) on the MSVC x64 Release build (Task 9).
2. **STOP and interrupts.** The firmware may wait in STOP or in a masked critical section while device interrupt levels change between slices. A masked level must not wake it, an unmasked one must, and level 7 must interrupt once per edge. Tests: `m68k_stop_wakes_on_unmasked_interrupt_only` and `m68k_level7_is_edge_triggered` (Task 7).
3. **Slice size.** Plan 6 runs the CPU in one-voice-slot slices. Running a program in 1-cycle slices or in one big slice must give identical registers, memory and cycle totals. Test: `m68k_slicing_is_invisible` (Task 7).
4. **Toolchain differences in edge arithmetic.** Shift counts of 32–63, `DIVS` of 0x80000000 by −1 and MULS sign extension behave the same on 32-bit MinGW and 64-bit MSVC, without undefined behaviour. Tests: `m68k_alu_divs_overflow_leaves_operand` (Task 4) and `m68k_shift_counts_32_to_63` (Task 5). The full suite runs on both builds (Task 9).
5. **Runaway execution into fill or garbage.** A PC that runs into 0xFFFF fill with garbage vectors must take line-F, double-fault and halt cleanly. `run` still returns and nothing crashes or spins. Test: `m68k_runaway_into_fill_halts_cleanly` (Task 6).

- Produces (namespace `ens::m68k`):
  ```cpp
  constexpr int kAutovector = -1;   // Bus::interruptAcknowledge: use vector 24 + level
  constexpr int kSpurious = -2;     // ... use vector 24
  struct Bus {
      virtual ~Bus() = default;
      virtual uint8_t read8(uint32_t addr) = 0;                // addr 24-bit
      virtual uint16_t read16(uint32_t addr) = 0;              // addr 24-bit, even
      virtual void write8(uint32_t addr, uint8_t v) = 0;
      virtual void write16(uint32_t addr, uint16_t v) = 0;
      virtual int interruptAcknowledge(int level) { (void)level; return kAutovector; }  // vector 0..255 or k*
      virtual void resetPeripherals() {}
  };
  struct Registers { uint32_t d[8]; uint32_t a[7]; uint32_t usp, ssp, pc; uint16_t sr; uint16_t prefetch[2]; };
  class Cpu {
  public:
      explicit Cpu(Bus& bus);
      void reset();                     // reset exception: SSP <- long at 0, PC <- long at 4, SR = 0x2700; 40 cycles
      int step();                       // exactly one instruction or one exception; returns cycles
      int run(int cycles);              // DECISION M6
      void setIpl(int level);           // 0..7 (Task 7)
      bool halted() const;
      bool stopped() const;
      uint64_t totalCycles() const;
      Registers regs() const;           // DECISION M3: pc/prefetch as in the suite
      void setRegs(const Registers& r); // also refills the internal IR/IRC from r.prefetch
      uint32_t instructionAddress() const;           // address of the last instruction started
      uint32_t exceptionCount(int vector) const;     // 0..255, for tests and the Task 9 smoke test
      std::function<void(uint32_t pc)> onInstruction;  // debug hook, called before each instruction if set
  };
  ```
- Produces (`m68k_decode.h`): `enum class Op : uint16_t { Illegal, LineA, LineF, Nop, ... };` and `Op decodeOp(uint16_t opcode);`, which is pure. Later tasks add enumerators and decode cases. The `Cpu` constructor fills a per-instance `std::vector<Op>` of 65536 entries and dispatches on it.
- Long accesses are two word accesses, high word first, except predecrement writes, which go low word first (UM).
- `tests/m68k_test_bus.h`: `struct RamBus : ens::m68k::Bus` holding 16 MB of bytes, with every address masked to 24 bits, plus `void load16(uint32_t addr, std::initializer_list<uint16_t>)`, `void load32(uint32_t addr, uint32_t v)`, `uint16_t peek16(uint32_t)`, `uint32_t peek32(uint32_t)`, a `resets` counter and an `ackVector` (default `kAutovector`). Tasks 1–8 all use it.

### Task 5: Logic, shifts, rotates and bit operations

**Files:**
- Create: `src/m68k/m68k_ops_logic.cpp`
- Modify: `src/m68k/m68k_alu.h`, `src/m68k/m68k_alu.cpp` (shift helpers), `src/m68k/m68k_decode.cpp`, `tests/test_m68k_alu.cpp`

### Task 8: Debug-trace disassembler

**Files:**
- Create: `src/m68k/m68k_dis.h`, `src/m68k/m68k_dis.cpp`, `tests/test_m68k_dis.cpp`

**Interfaces:**
- Consumes: `decodeOp` (Task 1).
- Produces:
  ```cpp
  struct DisLine { int length; std::string text; };   // length in bytes 2..10; text "move.l  #$c11138,($100).w"
  DisLine disassemble(const std::function<uint16_t(uint32_t)>& read16, uint32_t addr);
  ```
- The syntax is Motorola, lower case.
  - The mnemonic is padded to 8 characters.
  - `a7` prints as `sp`.
  - Numbers below 10 print in decimal and anything else as `$hex`. `trap` numbers print in decimal.
  - Absolute operands print the 24-bit effective address (`($ff8000).w`).
  - PC-relative operands print the target (`($c10012,pc)`), and branch targets print bare (`$c10012`).
  - An opcode that `decodeOp` calls `Illegal`, `LineA` or `LineF` prints `dc.w $xxxx` with length 2.
- This is for the emulator's debug trace only (design §5). No tool in this plan disassembles the ROM.

  - `m68k_dis_known_encodings`:
    - `4E71` → `nop`
    - `46FC 2700` → `move.w  #$2700,sr`
    - `21FC 00C1 1138 0100` → `move.l  #$c11138,($100).w` (8 bytes)
    - `13FC 0010 0028 0005` → `move.b  #$10,($280005).l`
    - `0839 0002 0026 0025` → `btst    #2,($260025).l`
    - `3038 8000` → `move.w  ($ff8000).w,d0`
    - `41FA 0010` → `lea     ($c10012,pc),a0`
    - `6100 0010` → `bsr.w   $c10012`
    - `6604` → `bne.s   $c10006`
    - `51C8 FFFE` → `dbf     d0,$c10000`
    - `4ED0` → `jmp     (a0)`
    - `4CDF 7FFF` → `movem.l (sp)+,d0-d7/a0-a6`
    - `48E7 FFFE` → `movem.l d0-d7/a0-a6,-(sp)`

    - `302E FFFC` → `move.w  (-$4,a6),d0`
